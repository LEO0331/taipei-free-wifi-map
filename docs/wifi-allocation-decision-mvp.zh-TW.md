# 臺北市公共 Wi-Fi 資源配置與數位近用決策支援 v1.0

## 1. 政策問題

當調查資源有限，哪些官方列載熱點應優先查證來源、現場狀況或文件缺口？本 POC 將政策問題轉為可追溯的證據審查名單。名額代表查核能力，不是設備預算、建置承諾或政府核定計畫。

## 2. 研究範圍

擴充既有臺北免費 Wi-Fi 雙語靜態地圖，保留附近搜尋、目錄、篩選、資料總覽、資料說明、Leaflet、PWA 與 GitHub Pages。新增獨立延遲載入決策頁。正式 MVP 為模式 A；模式 B、C 依實際證據門檻保持不可用。未新增後端、帳號、Google Maps API 或第三方地址地理編碼。

## 3. 官方來源

A 為資訊局新版公眾區免費無線上網熱點清冊；B 為圖書館；C 為區民活動中心；D 為運動中心；E 為行政區界；F 為全市網際網路服務統計；G 為資訊局營運說明。完整目錄、資源識別碼、原始位元組、SHA-256、取得時間、欄位、筆數、授權及排除原因見[來源稽核](wifi-allocation-source-audit.md)。下載成功不等於可納入決策；每個來源仍須通過用途相符的證據門檻。

## 4. 舊版與現行來源對帳

保留舊版 `Taipei_Free_AP_總表1141218.csv`，獨立取得官方 2026-07-01 公布版本 `A-2026-07-01.csv`。舊版 3,297 列，現行版本 3,305 列。這是來源清冊差異，不能直接解讀成實體設備淨增 8 台。對帳先查驗 SITE_ID、HOTSPOT_ID 及組合唯一性，再比較新增、消失、座標、分類與文件欄位；碰撞或缺失身分不猜測配對。

舊版取得時間不明，保留為未知；檔案修改時間不是下載日期。發布日期、取得時間、處理時間與版本雜湊分開保存。政策重建不更新來源取得時間，也不自動替換原地圖的版本。

## 5. 熱點與設施身分

一列熱點、單一實體地點、AP、政府設施及調查候選對象是不同統計單位。同一地點可以有多個識別碼，不能把它們當作各自服務一個社區。模式 A 使用來源限定的 site/hotspot 組合；碰撞時保留可檢查的來源列身分。相似名稱不能成立合併關係。未配對、排除及市外列均保留供稽核。

## 6. GIS 與鄰近語意

已公布位置的分布不同於兩點的幾何距離，兩者也不同於實測 RF 涵蓋。寬鬆座標框只能排除明顯異常，不能證明點位位於臺北市。行政區來源欄位可描述來源分類，但未宣稱經官方邊界定位驗證。B、D 座標尚缺完整權威 CRS／精度契約；C 的 X/Y 未確認 CRS；E 為 TWD97，多邊形轉換尚未完成驗證。因此本版不計算正式設施鄰近增益。

## 7. 證據資格

嚴格設定要求唯一可查的 site/hotspot 身分及來源所載臺北範圍；較寬設定允許可追溯的歧義或範圍疑問列進入查核，並未認證其位置或身分。舊版缺少現行對應者須另行允許納入。行政區與類別篩選在名額分配前套用；排除原因使用固定優先順序，以免同列重複計入排除總數。完整問題統計與互斥排除統計應分開解讀。

## 8. 模式 A：清冊與品質審查

依來源身分、座標、版本對應及文件問題分為 A／B／C 級。A 為主要證據查證；B 為文件補查；C 為較低優先的持續檢視。第一個成立的分級規則決定等級，再以穩定 ID 排序。等級衡量文件查核急迫性，不能推論現場斷線或居民損害。

## 9. 模式 B：假設設施調查

目前不可用。圖書館及運動中心資源已保留，但座標意義、精度、設施身分與地理資格尚未形成完整可驗證契約；活動中心 X/Y 與區界轉換亦未通過驗證。沒有用假座標或合成臺北案例替代。未來通過後才可用「官方設施來源＋經驗證設施 ID」作候選單位，明確公布參考設施分母、排除項與假設距離。100／250／500 公尺只可能是研究參數，並非官方訊號半徑。

## 10. 模式 C：營運及數位近用門檻

目前不可用。缺少可比的營運狀態、可用率、連線品質、使用量、共同時間窗、連續站點身分及人口／服務需求分母。全市使用統計不能任意分攤至熱點或行政區；熱點數不能代表低收入、數位弱勢或實際需求。本版不提供服務品質或數位排除排名。

## 11. 候選定義

候選是具有來源版本、可檢查身分及具體證據問題的清冊紀錄。表格呈現來源 ID、名稱、類別、來源行政區、問題碼、分級及版本狀態。全部候選不等於全部設施或全部應建置位置。市外紀錄保留為獨立範圍狀態；缺資料代表證據不足，不代表沒有服務。

## 12. 決策方法

方法版本為 `wifi-allocation-evidence-review-v1`，不用任意風險權重。「證據缺口優先」依分級及 ID 排序。「設施類別平衡」依官方類別分組，固定類別順序逐輪取一列，各組內保留分級／ID 順序；因此可能為類別代表性選入較低急迫問題。平衡不是公平性係數，也不是地區數位落差評分。詳見[方法文件](wifi-allocation-methodology.md)與實作。

## 13. 名額情境

提供 5、10、全部合格者。使用名額為上限與合格數較小者。輸出包含目標、來源版次、合格／排除數、設定、依序選取 ID、行政區／類別代表性、假設與不可用指標。策略比較僅限相同快照；全部名額可能選入相同集合但順序不同，應如實呈現等價。不限名額不是全數建置許可。

## 14. 敏感度假設

比較名額、嚴格／較寬身分與範圍門檻、是否納入舊版列，觀察合格數、排除原因、選取名單及代表性。較寬門檻只增加可調查問題，不能默默提高其證據可信度。模式 B 未通過門檻，距離敏感度與地理參考鄰近率均標示不可用，不計算居民涵蓋率或網路可用率。

## 16. 架構與效能

官方原始資料存於 `data/raw/wifi-policy/`，離線稽核／建置發布至 `public/data/wifi-policy/`。保留取得證據及原始雜湊；來源更新須明確下載、稽核接受後才變成新版本。瀏覽器在政策頁開啟時才請求政策快照，不執行重型 GIS 配對。既有地圖維持原來源，若需遷移，必須明確指定已驗證新版檔給原轉換器。檔案大小、建置及情境時間以[交付紀錄](wifi-allocation-delivery.md)實測為準，不宣稱公開主機延遲保證。

## 17. 測試與可重現性

使用既有 Node 測試框架及 TypeScript 建置，不新增套件。政策流程為 `npm run data:fetch:wifi-policy`、`npm run data:audit:wifi-policy`、`npm run data:build:wifi-policy`。相同保留來源重建必須產出相同快照雜湊。完整驗證仍包含 `./init.sh`、既有轉換、測試、建置、diff 檢查及桌面／行動瀏覽器檢查。實際執行結果及已知缺口由交付紀錄記載，本文不把規劃中的檢查當成已通過。

JSON／CSV 匯出包含快照、來源 URL／雜湊、方法、設定、真實選取 ID、排除理由、假設及責任使用說明；CSV 對公式起始字元加以保護。合成測試案例不得成為正式臺北結果。

## 18. 限制與後續工作

本版完成可查核的模式 A 證據準備度 MVP。尚需建立官方設施唯一身分、權威座標與精度、可靠區界轉換及存取條件，才能啟用模式 B；模式 C 另需營運、需求與分母資料。現場仍須確認開放時間、建物遮蔽、可進入性、電力、回程網路與設置權限。清冊差異不能證明設備實體增減，地理鄰近不能證明訊號或數位近用。後續作品集應保留來源治理、版本對帳、可解釋調查名單及工程驗證證據，再另行撰寫 Case Study 008。
